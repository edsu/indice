# Web interface i18n (Italian first) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve indice's whole web interface in the visitor's browser language when indice has it (English and Italian to start), falling back to the instance's `site.language`.

**Architecture:** A new `indice-lib` module `i18n` holds the compiled-in Fluent catalogs (`locales/en.ftl`, `locales/it.ftl`), negotiates a language per request from `Accept-Language`, and hands views an `L10n` handle on `Chrome`. Views, server error sentences, browser JavaScript (via a JSON data element) and indexing progress (via a new `Phase` enum) all take their words from it. Dates, numbers and sizes get small locale-aware formatters on `L10n`.

**Tech Stack:** Rust, axum, maud, `fluent-bundle` (concurrent bundle), `fluent-langneg`, `unic-langid`.

**Spec:** `docs/superpowers/specs/2026-11-06-ui-i18n-design.md`

## Global Constraints

- Single binary, pure Rust: new crates must build without a C toolchain and pass `cargo deny check` (CI runs RustSec + licences). No ICU.
- Catalogs are compiled in (`include_str!`); no runtime files.
- English is the reference catalog; `site.language` defaults to `en`; an unsupported `site.language` is a startup/config-load error listing supported languages.
- Language per request: first `Accept-Language` match among available catalogs, else `site.language`. Every language indice has is offered on every instance (no `site.languages`).
- Every response whose text depends on the language carries `Vary: Accept-Language`, appended to any existing `Vary`.
- Documented public API (`reference/api.md`: `GET /api/search`, `GET /api/annotations`, annotation/replay read endpoints, `/health`) stays English. Management `/api/` write endpoints, SSE streams and annotation write endpoints are UI internals and are translated.
- Error chains: translate only the sentence indice wraps around `{e:#}`; the chain stays as-is.
- AI description drafts use `site.language`, never the request's language; a custom `describe.prompt_file` is used unchanged.
- CLI output and `--help` stay English.
- Key terms (crawl, capture, collection, annotation, curator, archive, page, search) are Fluent terms at the top of each catalog, each with a `#` comment saying what it means in indice.
- No inline `<script>` (CSP): data for JS goes in `<script type="application/json">`, with `<` escaped as `\u003c`.
- Never wrap a translated string in `PreEscaped`; maud escapes it. Where a message must carry markup, split it into separate messages around the markup.
- Fluent isolation marks per language: off for left-to-right languages (`bundle.set_use_isolating(false)`), on for right-to-left ones (`ar`, `fa`, `he`, `ur`), where they keep LTR names and URLs from reordering the surrounding sentence. In LTR languages the U+2068/U+2069 marks only leak into `title`, attributes and JSON. Comment why at the call.
- Language tags are kept whole (language, script, region as the catalog names them), never cut to the primary subtag: Chinese needs `zh-Hans` vs `zh-Hant`, and `zh-TW` must match `zh-Hant`. Catalog file names are the tag (`en.ftl`, `it.ftl`, later `zh-Hans.ftl`).
- Plural forms for JS carry every CLDR category the language uses (Arabic has six: zero, one, two, few, many, other; Chinese and Japanese only `other`), never just `one`/`other`.
- Docs describe how indice works now (AGENTS.md). CI: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo build --workspace --locked`, `cargo test --workspace --locked`.
- Italian is Claude's best-guess draft, reviewed later by the Italian user; it may ship before review.

## Review Focus

1. **Messy `Accept-Language`**: q-values out of order (`en;q=0.5, it;q=0.9`), `*`, region-only matches (`it-CH`), uppercase, garbage bytes, an absurdly long header. Expected: best supported match or `site.language`, never a panic or 500. Test in Task 2.
2. **Zero and one in plurals**: Italian "0 raccolte" / "1 raccolta", English "0 crawls" / "1 crawl". Test in Task 4.
3. **Curator-controlled text inside translated messages** (a collection named `<img src=x onerror=alert(1)>` passed as a Fluent argument): stays escaped in Italian pages. Test in Task 5.
4. **A translation that would break the viewer page**: a string containing `</script>` or `{{replay_context}}` must not close the JSON element or fill a later slot. Test in Task 8.
5. **A key missing from Italian at runtime** (catalog edited by hand, test skipped): falls back to the English text, never shows the bare key or panics. Test in Task 1.

**Files:**

- Modify: `DESIGN.md` (new "Interface languages" section)
- Test: `crates/indice-lib/src/i18n/tests.rs`

**Interfaces:**
- Produces:
  - `pub const CATALOGS: &[(&str, &str)]`: `("en", include_str!("../../locales/en.ftl")), ("it", …)`. Adding a language = one `.ftl` file + one line here.
  - `pub fn supported() -> Vec<&'static str>`: language tags in `CATALOGS` order.
  - `pub fn parse_language(tag: &str) -> anyhow::Result<unic_langid::LanguageIdentifier>`: returns the supported catalog that `tag` negotiates to (case-insensitive; `it-IT` → `it`), else `Err` whose message lists `supported()`. Uses the same negotiation as `negotiate`, so `zh-TW` would find a future `zh-Hant`.
  - `pub fn negotiate(accept_language: Option<&str>, fallback: &LanguageIdentifier) -> L10n`: parses the header with `fluent_langneg::accepted_languages::parse`, orders by q-value if that function does not already (check; the q-value test pins it), then `fluent_langneg::negotiate_languages(…, NegotiationStrategy::Filtering)` with likely-subtags matching enabled (the crate's `cldr` feature, if that is what provides it), so script-bearing tags resolve; result is the first match, else `fallback`. Headers longer than 1 KiB are ignored (treated as absent).
  - `#[derive(Clone, Debug)] pub struct L10n` with `impl Default` (English):
    - `pub fn lang(&self) -> String`: the catalog's full tag (e.g. `"it"`, later `"zh-Hant"`); used for `<html lang>`.
    - `pub fn dir(&self) -> &'static str`: `"rtl"` for `ar`, `fa`, `he`, `ur`, else `"ltr"`; emitted as `<html dir>` from Task 2 on, so an RTL catalog needs no template change (its CSS work is separate, see DESIGN).
    - `pub fn tr(&self, key: &str) -> String`
    - `pub fn tr_args(&self, key: &str, args: &[(&str, FluentArg)]) -> String`, where `pub enum FluentArg<'a> { Str(&'a str), Num(i64) }` (plural selection works on `Num`).
    - Lookup order: chosen language → English → the key itself, with `tracing::warn!` on the last two.
  - Bundles live in a `static BUNDLES: LazyLock<Vec<(LanguageIdentifier, fluent_bundle::concurrent::FluentBundle<FluentResource>)>>` so `L10n` is just an index into it (cheap `Clone`, `Send + Sync`).
